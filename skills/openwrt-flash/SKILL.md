# OpenWrt 安装、升级与恢复

目标是完成用户授权的安装或修复，并以实际启动和联网证据验收。尽量用中文解释操作影响，固件文件名、命令和设备 ID 保持原文。

## 1. 建立现场证据

先记录：品牌、完整型号、硬件修订、地区版、当前系统、启动介质、主机系统、当前网关、管理入口，以及本次是首次安装、升级、恢复还是只排障。

- 设备标签、官方设备页和 `ubus call system board` 交叉核对。营销速率名称、SSID、SoC 相同或外壳相似不能证明固件兼容。例如 AX9000 与口误 VX9000 不可直接当作相同型号。
- 对已登录 OpenWrt，可运行 [router_inventory.sh](scripts/router_inventory.sh)。它只是证据的一部分；缺少数据标为未知，不默认成功。不要为“检查状态”启动或停止服务。
- 不扫描整个局域网找设备。先用用户提供的入口、本机路由表、已知 DHCP/邻居信息和物理接线确定目标。
- 本次刷机没有自动授权改 AP 模式、VPN、DNS、广告过滤、远程暴露或安装第三方包。用户明确要求这些时再处理。
- 用户在终端输入密码，优先使用现有 SSH 认证/连接复用；避免反复安装临时 authorized_keys。确需临时密钥时记录唯一标记，成功或失败均删除本次授权并关闭会话，不改变其他密钥。
- 不读取或上传整个配置目录作为诊断输出。备份可能含 PPPoE、Wi-Fi、VPN 凭据，留在私有目录，权限限制为当前用户。

## 2. 查证兼容性与方法

读取 [官方来源与证据记录](references/sources.md)。按设备完整名称在当前官方设备页、Firmware Selector 和下载目录中核对支持状态、profile、target/subtarget、限制与安装路径。版本号和文件名都在执行时确定，不把本 skill 编写时的版本称为“最新”。

来源无法访问时，不猜设备专用步骤。可查官方源码中的 profile/image recipe 和发布说明交叉验证；仍缺首次安装/恢复细节时，明确所缺证据并请求设备资料。对于厂商 fork、社区固件与官方 OpenWrt，先确认区别和迁移限制，不默认互刷或混用 feed。

选择一个分支：

| 现场情况 | 读取参考 |
| --- | --- |
| SD/TF、离线 USB/SATA/NVMe 整盘安装、x86 或 VM | [介质与 x86](references/media-and-x86.md) |
| 原厂内置 NAND/NOR/eMMC、已有 OpenWrt、双分区或恢复 | [内置闪存与升级](references/embedded-and-upgrade.md) |
| 根分区扩容、刷后网络、DNS/代理/广告过滤故障 | [刷后验证与排障](references/postflight.md) |

型号没有官方支持时报告限制，不用相似型号镜像试刷。品牌覆盖表示可识别和选择流程，不是固件兼容承诺。

## 3. 下载、校验与备份

下载精确匹配的官方镜像及对应校验清单，使用正常 TLS 校验。结合官方签名说明验证清单的可信来源；从同一不可信镜像站取得文件和散列不能证明来源真实。

在主机上使用以下只读工具；参数换成现场确定的路径和可信散列：

```sh
python3 scripts/verify_firmware.py /path/to/firmware.img.gz --sha256 TRUSTED_64_HEX_DIGEST
```

脚本只证明文件散列和可选 gzip 完整性、大小，不证明机型兼容、签名可信、磁盘安全或可启动。gzip 的压缩大小不等于所需介质大小。需要与介质容量比较时使用解压后的大小。

备份现有配置及必要恢复材料，确认备份已复制到路由器之外并可读；sysupgrade 备份不是完整闪存克隆，也不自动备份所有已安装包。存储校准数据的 ART/factory/EEPROM、bootloader 和设备身份区遵循设备文档单独保护，不覆盖、不与其他设备互换。

## 4. 执行前说明与写入

提交简洁的具体执行摘要：目标设备及硬件版本、镜像来源和 SHA-256、将被覆盖的介质/分区、配置保留策略、恢复方法、预计断网影响。现有授权清楚覆盖这些内容时继续；若只知道“disk5”而介质已重插，重新识别，不能沿用旧编号。

写入前立即核对一次介质身份。执行设备专用的已核实流程：

- 整盘镜像写入必须是已卸载、非当前系统盘的目标整盘；不把压缩流未经校验直接管道输入写盘命令。
- 原厂首次安装遵循该型号文档；不把 sysupgrade 镜像直接上传原厂页面，不给任意型号套用 `mtd write`、`nandwrite`、`ubiformat` 或 bootloader 环境命令。
- OpenWrt 升级先在设备上核验镜像并运行 `sysupgrade -T`。失败时检查镜像、布局和升级路径，不能用 `-F` 绕过。即便测试通过也不能省略硬件与来源核实。
- root 权限只用于需要的步骤。安装/服务命令若从 SSH stdin 传入，应保存受控脚本后执行，或给会读 stdin 的子命令重定向 `/dev/null`，防止吞掉后续命令。
- 刷写中 SSH 断开不等于成功，也不等于失败。不盲目重试刷写或断电，先按设备启动/恢复方式观察。

## 5. 验收和交接

根据 [刷后验证](references/postflight.md) 验证启动、版本/板型、存储、管理入口、LAN/WAN、DNS，以及真实客户端流量。进程存在、HTTP 页面打开和网页测试卡片都不是完整网络验收。

清理本次临时授权、临时凭据和私有诊断文件。提供精简结果：实际系统版本、入口、关键测试结果、备份位置、尚未验证事项。不要宣称所有设备适配或所有网站正常，也不要把本次凭据写进可分享 skill。
