# SD/TF、整盘镜像、x86 与虚拟机

## 型号与启动方式

NanoPi R2S/R4S/R5S/R6S、Raspberry Pi 各代只是候选家族示例。逐台核对官方 profile、板卡修订、内存变体、引导器和启动介质。TF 启动步骤不能直接等同于 eMMC 安装；ROM 启动优先级和 SPI bootloader 也可能影响启动。

x86 要核对 CPU 架构、UEFI/传统 BIOS、EFI 镜像变体、网卡驱动、Secure Boot 和根文件系统。不要仅因为设备叫“软路由”就选 x86_64。ext4 和 squashfs 的可写层、恢复和扩容方式不同。虚拟机按平台接受的磁盘格式与虚拟网卡配置，转换前保留原镜像，明确是否使用快照；不能把 VM 导入步骤变成宿主磁盘刷写。

## 主机只读盘点

按主机系统选一种，不自动执行写入：

| 主机 | 盘点方式 | 需要排除 |
| --- | --- | --- |
| macOS | `diskutil list -plist`、`diskutil info -plist /dev/diskN`，使用 plist 解析 | APFS 容器的物理系统盘、内部盘、多路径别名、分区与整盘混淆 |
| Linux | `lsblk -J -b -o NAME,PATH,TYPE,SIZE,MODEL,SERIAL,TRAN,MOUNTPOINTS`、`findmnt /` | 根、boot、EFI、swap、LVM、LUKS、RAID 的所有父设备；外置系统盘也不能写 |
| Windows | PowerShell `Get-Disk`、`Get-Partition`、`Get-Volume`，用 `ConvertTo-Json` 结构化 | `IsBoot` / `IsSystem`、Storage Spaces、页文件所在盘、分区与物理磁盘编号混淆 |

命令选项依实际版本调整。插卡前后对比设备列表，再核对容量、总线、型号、序列号、整盘标记和挂载点。私有设备标识只用于本机核对，不写入公开报告。

“Removable=false”不一定表示不能刷，“外置盘”也不表示可以刷；系统盘可能通过 USB 启动。无法追溯根文件系统到物理盘时不做自动刷写。

## 写入流程

1. 下载和验证精确板型的整盘镜像。确认格式是真正 raw disk image；`.bin` 或 `.img` 扩展名不能单独决定用途。
2. 对 gzip 文件先校验压缩文件的官方散列、完整性和解压大小。充分预留主机解压空间和目标盘容量。
3. 在私有工作目录解压为普通文件，再核对其字节数。不要用 gzip 尾部 ISIZE 作为超过 4 GiB 文件的唯一长度依据。
4. 备份目标盘已有数据。向用户说明本次写入的是哪张卡或哪块盘、容量和将清空的内容。卸载目标所有卷，然后重新确认身份；介质拔插、重启或设备编号变化后必须重新绑定目标。
5. 由已批准的 GUI 镜像工具或经检查的本机写盘工具执行。若使用 `dd`，从已验证的普通镜像读入，输出精确整盘设备；macOS 的 `/dev/rdiskN` 与 `/dev/diskN` 是同盘不同接口，不是两块盘。不同系统的进度参数不同，不盲用 GNU 专用选项。
6. 等工具退出成功并同步缓冲。卸载/离线状态下，重新读取目标盘**镜像字节长度范围**并与解压镜像比较；不要比较整张更大卡的散列。写入验证工具成功也只能证明写入，不等于启动成功。
7. 安全弹出，接到目标设备启动。首次验证管理口/网口角色，不根据外壳左右位置假定 WAN/LAN。

## 扩容

不要在刷机同时默认扩容。确认用户需要、磁盘空间分布、分区表和文件系统之后再做。GPT 备份表、分区起始扇区、root UUID/PARTUUID、loop overlay、squashfs、F2FS 都会改变方案。

只移动受文档支持的结束边界，不移动启动扇区或覆盖后续分区。工具支持在线扩容和离线校验的条件分别核实。后续 sysupgrade 可能恢复镜像布局；把升级后的容量检查纳入验收。不能把一次 R2S ext4 扩容命令复制到所有设备。
