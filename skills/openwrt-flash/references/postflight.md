# 刷后验收与经验边界

## 从设备到客户端

按路径检查：物理链路 -> 地址/路由 -> DNS -> TCP -> TLS/HTTP -> 应用。分别记录执行测试的位置。

- 设备：实际 OpenWrt 版本与板型、root/overlay 容量、空闲内存、只读挂载或 I/O 错误。`df /overlay` 不总存在，ext4 根目录可能就是 `/`。
- 管理：在已确认 LAN 网段访问 LuCI/SSH；没有 LuCI 不一定是坏镜像，先查构建内容。不要给 WAN 开放管理端口作为快捷修复。
- WAN：核实 DHCP、PPPoE 或静态配置与运营商条件。LAN/WAN 网段重叠、接口顺序变化、双 DHCP 都会导致“能打开管理页但不能上网”。
- DNS：检查明确指定解析器的 A/AAAA 查询和响应码。`no-answer` 可能是 NODATA、NXDOMAIN 或失败，不等同广告拦截。
- 客户端：默认网关不是 R2S 不证明流量不经过 R2S，前级路由器仍可能以 R2S 为上游。核对完整拓扑和路由；有条件用连接/计数证据确认路径。
- 联网：选至少一个国内和一个国际 HTTPS 端点，检查 curl 退出码和 HTTP 状态。必要时使用 `--noproxy '*'` 并核对本机代理环境，避免把 Mac VPN 的结果归功于路由器。透明代理仍可能存在，需要额外路径证据。

最终联网验证启用证书校验；`-k` 只用于已说明原因的证书诊断，不能作为安全 HTTPS 通过的证据。HTTP 200/204 说明一次应用请求成功，不说明吞吐、UDP、IPv6、全家设备或所有网站均正常。HEAD 返回 405/501 时可改 GET 验证，不直接判断网络失败。

检查进程时避免 `pgrep -f` 匹配执行检查的 shell 自身；读取 procd/ubus 的实际实例状态或精确进程，并与端口和请求结果结合。进程正在运行不意味着配置已生效。

## 可选软件与 DNS/代理

仅在用户要求时配置，先读取实际版本和服务实现。优先最少必要组件，不默认叠加多个 DNS 劫持服务和多个高度重叠的大广告列表。

adblock-fast 的 enabled、自启、列表启用、规则生成、DNS 加载和实际客户端拦截是不同状态。精简 dnsmasq 可能缺 NFTSet；安装 dnsmasq-full 属于会影响 DHCP/DNS 的变更，要评估替换兼容性和恢复。已有 PassWall2 的独立 dnsmasq 可能绕过系统列表，不能只测 127.0.0.1 就宣称全网拦截。

PassWall2 故障时区分：节点本身、远程 DNS、路由器自身透明代理、LAN 代理、订阅访问方式。所谓“订阅直连”是否真的绕过透明代理由当前版本实现决定；读取代码并对比测试，不把选项名称当作保证。

关闭 Localhost Proxy 可能恢复订阅，也可能使路由器 Google 卡片检测失败；这与 LAN 是否正常不是同一件事。优先设备支持的按域名/目的地址直连规则和独立可用 DNS，并验证节点失效时的订阅更新。

不要把历史上“每 30 秒将解析到的订阅 IPv4 加入 psw2_vps”作为通用修复：存在首次启动竞态、DNS 阻塞、TTL/旧 IP 累积、CDN 共用 IP、重定向、IPv6 和防火墙重载问题。任何辅助服务须有明确范围、失败处理、刷新/过期策略、恢复步骤，并单独授权部署。

故障演练先使用隔离测试出站或专用测试实例。不要为验证订阅随意冻结生产 Xray；若授权短暂停服演练，需有独立限时恢复机制、限定窗口及恢复后的真实验证。不要以 CLI 返回 0 和旧节点数量推断订阅成功：检查实际下载结果、更新状态及新配置是否有效，日志须在输出前去除 URL 查询参数和节点密钥。

## 维护

根分区扩容、第三方包、静态绕行和自定义 procd 服务都可能不被默认 sysupgrade 备份包含。记录其必要路径及依赖，升级后重验，不直接复制未知脚本到新固件。
