# 内置闪存、升级和救援

## 原厂首次安装

首先确定完整型号、硬件修订、地区、原厂固件版本以及精确官方安装页面。厂商可能限制固件签名、升级顺序或当前原厂版本；先确认能否按文档获得所需入口。

按文档选择原厂 Web、恢复 Web、TFTP、initramfs 临时启动或串口流程。方法之间不互相替换。确认文件的 factory/sysupgrade/initramfs/recovery 角色，文档指定的上传文件名、接口、服务器/设备 IP、按键时序和校验结果。不自动刷 bootloader，不套用第三方解锁脚本。

NAND、NOR、eMMC 写法不通用。存储设备名、MTD 分区编号、擦除块大小、UBI 容器和双分区标记都从现场与对应文档获取，不猜测。双分区路由器还需记录当前槽位、启动计数、恢复槽位与是否会覆盖回滚镜像。

如果需要 UART，核对电平和针脚，通常只接文档要求的 GND/TX/RX，不凭通用经验接 VCC。设备不支持或无法确认恢复方式时先交付诊断，不冒险试刷。

## 现有 OpenWrt 升级

1. 获取板型、版本、target、存储和引导模式，查当前版本到目标版本的迁移说明。特别注意 swconfig/DSA、设备 profile 更名、分区布局变化、厂商 fork 和跨大版本。
2. 用 `sysupgrade -l` 确认备份范围；创建配置备份，复制到主机并验证可读。单独保存必要包清单和自定义服务路径。包管理器通过 `command -v apk` / `command -v opkg` 识别，不能根据旧对话或日志建议猜。
3. 用户希望保留软件包时，可评估当前设备/版本支持的 Attended Sysupgrade、LuCI、owut 或其他官方工具。它们有自己的适用范围；普通 sysupgrade 备份不会完整保留所有额外软件。
4. 镜像放到足够空间的临时位置。传输后核对 SHA-256。运行 `sysupgrade -T /tmp/verified-image`，检查退出码和输出。不要在命令行打印任何凭据。
5. 按迁移兼容性决定保留或重置配置。涉及清空且现有授权未覆盖时说明具体后果；不为了方便默认 `-n`，也不盲目保留不兼容配置。
6. 成功通过检查后按文档执行 sysupgrade。镜像后缀不一定是 `.bin`；x86 等设备可能使用整盘镜像，不应凭名称排除。
7. 等待设备重新出现，在正确网段重新连接。SSH host key 变化需要用设备重装证据确认，不能全局关闭 host key 检查。核对实际版本与板型，再恢复兼容的业务配置。

禁止无差别 `opkg upgrade` / `apk upgrade` 代替固件升级，也不混装不同版本内核模块、不同架构包或第三方 feed。不因依赖冲突自动使用 force-overwrite。

## 恢复

先区分配置失联、启动失败和硬件损坏。正常 failsafe、恢复出厂配置、厂商救援与串口 bootloader 恢复各有条件。

- 配置失联：核对物理端口、管理网段、本机 VPN/代理和 DHCP，必要时使用该型号支持的 failsafe；不先重复刷写。
- 镜像不启动：保留已有刷写结果和日志，按文档启动救援。TF 设备优先使用已知良好备用卡，不先覆盖唯一原卡。
- NAND/双槽位：先检查已知恢复槽位，保护校准分区和设备身份。备份只回写同一台设备的正确区域。

恢复是否成功以实际启动/版本/管理及联网验收为准。无法完成时明确设备停在哪个阶段，不声称“工具退出即刷机成功”。
